# CAD 更新资产名称迁移决策材料（待跨项目批准）

此文为提案，不改变现行跨项目协议、正式资产名称或任何已发布 Release。项目当前不具备发布就绪状态。

## 受影响版本和现状

- 仓库标签 v1.11.0、v1.11.7 的 Runner 源码及当前 v1.11.10 Runner 都仅识别 `Honsen_DrawTranslate_vX.Y.Z_Setup.exe`；v1.11.0–v1.11.10 的实际已发布与本地构建分布应以各 Release 和标签复核，不可假设每个版本均公开可用。v1.11.0、v1.11.1 已有撤回记录；v1.11.4 无对应标签。
- v1.10.0 的主程序更新器接受旧 `Honsen_DrawTranslate_vX.Y.Z_Setup.exe` 及历史 `HonsenCAD.vX.Y.Z.exe`，按 Release tag 查找、要求 GitHub API `sha256:` digest、下载后计算 SHA-256。未安装 Runner 的更早版本及不能运行的 Runner（包括历史提示窗口问题）需逐版本核实，不应承诺自动迁移。
- 现有 Runner 自行读取 GitHub latest，按旧名称匹配并比较 API digest；Toolbox 也下载和检查 digest，但 Toolbox 当前无第三方 Runner apply 调用。仅发布新名称将使旧 Runner 无法发现安装包。旧 Runner 的名称版本检查曾使用子串匹配，需在过渡中将来源视作不可信。

## 需要跨项目决定

方案 A：先发布一个仍沿用旧名称的过渡 Release，安装能识别未来新名称的 Runner，并附同名 `.sha256`；待有证据证明覆盖率足够，再按批准的统一名称发布。旧名称与规范 `<ProductId>-<version>-Setup.exe` 的差异须先批准；无法自动覆盖的离线、跳版、关闭更新或旧版本用户仍需人工介入。

方案 B：同一 Release 同时上传新旧两个安装包名供旧客户端发现，但这与稳定 Release 只能有一个可安装资产的规范冲突；不得在未经批准时执行，也会增加工具箱选错资产和摘要不一致的风险。

方案 C：切换新名称并要求旧版用户从可信渠道手动下载、验证 digest 和在原目录安装；会中断静默更新，且已有旧卸载日志的数据安全尚未验证。不能把手动安装称为无风险的自动迁移，也不能承诺不会改目录。

## 必要验收与回滚

在可恢复的 Windows 10/11 虚拟机分别从 v1.10.0、v1.11.0、v1.11.7、v1.11.8、v1.11.10 及确认存在的历史版本的干净快照出发，验证旧名称过渡、跳版、离线、错误 digest、重试、UAC、Unicode 原目录、用户数据及卸载日志。记录正式 API asset digest、sidecar 和安装后注册表/Manifest/EXE 版本；测试失败和回滚应先还原 VM 快照并核对数据，不修改已发布 Release。对已投放客户端，回滚仅能通过事先批准的更高版本修复或文档化手动恢复，不能假定旧版卸载/降级安全。完整试验通过并获得跨项目批准前禁止切换名称。
