# v1.9.4 PRD：幕墙专业分类

## 目标

在既有专业分类中新增“幕墙”，让幕墙图纸可使用独立的本地术语和翻译记录，同时完全兼容既有通用、建筑及其他专业数据。

## 范围

- 所有四个翻译方向的专业分类增加 `facade`（界面名称：幕墙）。
- 单文件、批量任务、方向术语库、内置术语和翻译记录均接受并保留该分类；批量开始后锁定当次选择。
- 查找顺序保持不变：幕墙用户术语 → 通用用户术语 → 幕墙内置术语 → 通用内置术语 → 幕墙翻译记录 → 通用翻译记录 → 翻译服务。
- 四个 YAML 术语表声明 `facade` 为允许的专业字段。没有幕墙字段的已有术语继续使用其 `general` 值。
- 启动默认仍为“通用”；不迁移、不改写已有术语或翻译记录。

## 非目标

- 不把现有“建筑”术语自动复制、迁移或重分类为“幕墙”。
- 不基于图层、图框或文本内容自动猜测幕墙专业。
- 不向 DeepL 或 Azure 发送专业分类或提示词。
- 本版不添加未经图纸或客户确认的幕墙术语。

## 验收标准

1. 界面设置和语言资产窗口都显示“幕墙”，新建的单文件与批量请求能通过服务端校验。
2. 幕墙用户术语、内置术语和翻译记录均优先于通用对应项；其他专业的记录不相互命中。
3. 幕墙没有专用项时，完整标签继续回退到通用项或翻译服务。
4. 旧 SQLite 数据、既有 YAML 术语和现有六个分类不发生迁移或行为变化。
