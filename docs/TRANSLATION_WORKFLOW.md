# CAD 翻译流程与批量队列

> 本文归集现行翻译流程与批量队列要求。语言资源及优先级见 [LANGUAGE_ASSETS.md](LANGUAGE_ASSETS.md)，完整测试与发布门禁见 [TEST_RULES.md](TEST_RULES.md)。历史设计稿见 [v1.9.2 PRD](PRD_v1.9.2.md)。

## 目标

批量队列支持可恢复的 DXF/DWG 翻译、四种语言方向、可控并发、失败重试和每个任务的明确结果。

## 队列模型

入队时每项只保存源文件绝对路径和入队顺序；输出目录、输出格式与版本、是否翻译块、语言方向与翻译服务在点击“开始翻译”时统一注入待执行任务。任务状态包括 `queued`、`running`、`retrying`、`succeeded`、`failed`、`cancelled`；暂停是队列级 `paused` 标志，不是任务状态。

- 同一批队列只翻译到一个目标语言；切换语言只作用于尚未开始的任务。
- 默认按入队顺序调度；用户可暂停/继续整个队列、移除未运行任务、对失败或完成任务单独重翻。主“开始翻译”会把全部待执行、停止或失败项按当前设置重新排队，适用于切换翻译服务或更换 Key；单项“重翻”保留上一次开始时的任务设置。
- 每个任务独立输出，不覆盖源文件；默认输出名使用目标语言前缀和源名。
- DWG 通过 ODA 转为工作 DXF，完成后按用户选择的 DWG 版本输出；DXF 可按用户选择的 DXF 版本保存。
- 应用退出或异常时，将任务输入、状态、重试次数、输出路径和进度写入本地队列状态文件；重启后恢复为可继续状态，未完成的 `running` 任务改回 `queued`。

## 并发与翻译服务防护

- 当前队列按 API Key 限制同时最多 **2** 个文件，全局最多 **3** 个运行任务；DWG 的 ODA 转换另受串行锁限制。
- 不做高并发带宽探测。真实 API 调用会消耗配额且可能触发风控；只在真实验收文件上观察 429、超时和平均响应时间。
- 每个 API Key 使用共享文件级限流器；可重试错误按 2、4、8 秒退避，最多重试 3 次。
- Azure Translator F0 的 `403001` 免费额度耗尽错误不可重试；任务直接失败并提示等待下月额度重置或升级资源。
- DWG 的 ODA 转换串行化，避免多个 ODA 进程抢占临时文件或内存；DeepL 文本请求仍可在文件间并行。

## 界面验收范围

- 采用已确认的“顺时针旋转品字形”布局：左上翻译队列、左下实时日志、右侧翻译设置贯穿全高；左侧高度中队列占 70%，日志占 30%。
- 添加文件或将 DXF/DWG 拖入翻译队列、选择输出目录、批次统一语言方向、输出格式与 DWG/DXF 版本。拖入文件会保存为本地接收副本，保证队列重启后仍可恢复。
- 实时日志支持清除与导出；导出通过系统保存对话框生成 UTF-8 文本，后端最多保留最近 5,000 条会话日志，超出后自动淘汰最旧条目。
- 可见的队列顺序、任务状态、文件级进度、整体进度条与百分比。
- 启动、暂停、继续、移除、失败重试、单文件重翻、成功/失败提示。
- 每个任务显示输出路径、错误摘要和可复制的完整日志；成功任务可在 Windows 资源管理器中直接定位输出文件。

## 自动验证

1. 队列状态序列化与恢复；运行中任务重启后能安全重排队。
2. 顺序调度、暂停/继续、移除、重试次数和单项重翻。
3. 输出格式、版本及 `fr_`/`en_`/`zh_` 前缀。
4. 限流、429 退避和一次失败后成功的重试路径。
5. 队列及配置写入必须使用同目录临时文件和原子替换；损坏的 JSON 要隔离为带时间戳的 `.corrupt-*` 文件后恢复为空状态。
6. 最多保留 100 个已结束任务（运行中的任务不清理）；拖入文件副本仅在无活动任务引用且超过 30 天后清理。
7. 每个 SSE 订阅队列上限为 500 条，慢客户端丢弃新增推送而不阻塞翻译。
8. CAD 最终输出先写入同一目录的临时文件，成功后原子替换；失败时不得覆盖既有目标文件。

## 真人端到端验证

使用至少一份 DXF 与一份 DWG，依次执行中文→法语、法语→中文、中文→英语、英语→中文：

1. 入队多个文件，确认按序显示；以默认并发 2 启动。
2. 任务运行中暂停、恢复、移除一个未运行项，并对一个完成项重翻。
3. 人为制造一次可恢复的网络/API 失败，确认退避重试、错误提示和不中断其他任务。
4. 中途退出并重启，确认未完成项可恢复且不会重复覆盖输出。
5. 使用 CAD 查看器打开全部成功输出，确认 DXF/DWG 格式、所选版本和译文文字正常。

## 可选预处理：智能合并拆行文字

### 目标

为 CAD 图纸中被拆为多个相邻 `TEXT` 实体的短标签和房间名提供一项可选的本地预处理能力。开启后，软件先将符合严格几何规则的拆行文字合并为一个完整短语翻译，再按原行数写回，避免逐行翻译造成语义断裂。

### 范围

- 翻译设置增加 `智能合并拆行文字` 开关，默认关闭；单文件请求携带该设置，批量任务在开始时锁定该设置。
- 只处理模型空间和图纸布局中的普通 `TEXT` 实体；不处理 `MTEXT`、属性文字、尺寸文字、表格、块定义或长段落。
- 仅合并同一图层、同一文字样式、同一高度和旋转角度，且在垂直方向紧邻、水平位置对齐的短文本行；单组最多三行、合并前后均受短标签长度限制。
- 每个合并组只执行一次既有术语/记录/翻译服务查找，继续使用当前专业分类和语言方向逻辑；不向 DeepL 或 Azure 发送额外上下文。
- 翻译结果按原有行数重新分配：优先按单词边界拆分，中文等无空格结果按字符比例拆分，保留原实体和其位置。
- 不满足规则的实体继续逐条翻译，行为与关闭开关时一致。

### 非目标

- 不自动合并段落、注释、说明文字或任意彼此接近的 CAD 文字。
- 不修改源图纸中的实体数量、图层、样式、旋转或坐标。
- 不引入 OCR、模糊语义匹配或新的第三方依赖。

### 成功标准

1. 默认关闭时，所有 `TEXT` 保持原有逐实体翻译行为。
2. 开启后，类似 `Salle de` / `Réunion/Salle des` / `Parents` 的相邻房间名会作为完整标签翻译一次，并写回对应的原始行数。
3. 不同图层、样式、尺寸、旋转、未对齐或间距过大的文本不得被合并；`MTEXT` 必须保持原路径。
4. 合并后的翻译仍遵循 [语言资源](LANGUAGE_ASSETS.md) 中的专业分类术语优先级。
5. 单文件和批量界面均可设置该选项；已开始的批量任务不受后续界面修改影响。
